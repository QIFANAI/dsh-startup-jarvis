# v0.5 · 第一幕（钢铁侠）重做规划

> 只改 0.0–3.2s 的第一幕；其余阶段保持 v0.4 现状（用户已认可）。
> 已做可行性验证：用素材帧提取"装甲边缘蒙版"再叠金色辉光，效果见 `out/masktest/preview-b.png`（960×540 预览）。

## 1. 为什么 v0.4 的第一幕"差意思"（先诊断）

| 问题 | 具体表现 |
|---|---|
| **效果浮在屏幕上，不贴在装甲上** | 锁定框、径向光束、漂浮标签都是屏幕坐标的图形，看起来像"套了个游戏 UI"，与装甲本体无关 |
| **锁定框是错的语汇** | 方框收拢=射击游戏/无人机瞄准，不是 JARVIS 的"系统自检"；而且四角飞到胸口显得生硬 |
| **配色冲突** | 装甲是赤红+金+暖光，叠加层却以 DSH 青为主，画面两套色系打架 |
| **信息密度过高** | 6 组漂浮标签 + ticker + 四角框 + 光束 + 粒子，第一幕只有 3 秒，观众来不及看 |
| **缺"身体在动"的感觉** | 能量环、光束都在空间里扩，装甲本体没有任何变化 |

## 2. 解法核心：把特效"长"在装甲上

**离线从素材里提取装甲的边缘/高光蒙版**，运行时用蒙版驱动发光——效果与装甲轮廓逐帧严丝合缝，这是"贴车身"与"贴屏幕"的本质区别。

已验证的技术路线（`scripts/mask-test.py` 跑通）：

1. 对 0–3.2s 逐帧（96 帧）做 Sobel 边缘检测 → 得到装甲分件线/轮廓
2. 用"主体掩膜"（亮度过阈值 + 连通域 + 范围收缩）压掉素材自带的背景 HUD 线条（否则背景环线也会发光，显脏）
3. 输出 960×540 灰度 PNG 序列 `assets/masks/edge_000.png … edge_095.png`（约 8–12MB），运行时按帧取用
4. 额外输出 `assets/masks/lum.json`（每帧平均亮度），用于自动调节强度（画面越暗，辉光越明显）

|---|---|---|---|

## 2. DSH 文字与动效体系（"更科技"的核心）

### 2.1 字体层级（4 级，取代现在的随手排版）

| 级别 | 用途 | 规格 |
|---|---|---|
| Display | 品牌字标 / Logo slam | Consolas Bold，44–76px，字距 12–24，扫描显影入场 |
| Data | 数值（计数/温度/百分比） | Consolas，18–22px，数字滚动 + 单位小一号灰色 |
| Label | 字段名/状态 | Consolas，10–12px，字距 6，全大写 |
| Unit | 单位/注脚 | Consolas，9–10px，灰色 40%，字距 2 |

### 2.2 动效语法（统一动作库，每个元素只用这 8 种）

1. `decode` 乱码解析（0.35s：随机字符 → 逐字落定）
2. `draw-in` 细线绘制（括号/分隔线从左到右画出来）
3. `stamp` 盖章（0.12s 缩放 1.4→1.0 + 白闪）
4. `count` 数字滚动（0 → 目标值，easeOut）
5. `sweep` 扫描带（1px 亮线 + 拖尾掠过区块）
6. `glitch` 短故障（RGB 分离 2–4px + 水平错位，仅冲击点用，≤80ms）
7. `rotate` 环形刻度旋转（慢速，8–20°/s）
8. `blink` 状态灯闪烁（2Hz 方波，只用于 ACTIVE/READY）

### 2.3 HUD 结构（三件套，全片统一）

- **Corner frame**：四角括号 + 分段边（每边 3 段，间隙 6px）
- **Panel**：半透明底板（黑 0.45）+ 顶部标签条 + 右下角编号（如 `P-03`）
- **Ticker**：底部或顶部滚动事件流（`12:04:11 KERNEL OK` 这类，来自 boot 阶段状态机）

### 2.4 全片 HUD 骨架

| 位置 | 元素 |
|---|---|
| 左上 | `DEEPSEEK HARNESS` + 副标 `BOOT SEQUENCE / JARVIS` + 3 条状态灯 |
| 右上 | `T+xx.xxs` / `FRAME nnnn` / `30FPS` + 实时 CPU/MEM 假读数（滚动） |
| 左下 | `BUILD 0.2.2-rc.1 · PROFILE desktop` + 进度百分比 |
| 右下 | `[ SKIP ] ESC`（3s 后淡入）+ 阶段编号 |
| 底部 | 细进度条（1px，全片持续） |
| 中央 | 阶段主视觉（见 §3/§4） |

## 5. 逻辑（"逻辑"指什么，本次明确）

1. **阶段状态机**：6 个阶段（IGNITION / VOICE / LOAD / CHECK / SLAM / HANDOFF），每阶段 enter/exit 事件驱动 HUD 与动效，避免"一堆 if"。
2. **音频事件驱动**：由 `envelope.json` + `onsets.json` 触发（如冲击点触发 glitch、峰值触发环外扩）。
3. **真数据注入**：插件宿主读 facts（SKILLS 数 / BUNDLES 数 / MODEL / SESSION / 版本 / 平台）→ 注入 overlay 的 `window.__JARVIS_FACTS__`；预览片用等价假值。
4. **可跳过 / 看门狗 / 降级**：沿用 v0.3 规划（Skip 480ms 短交接、8s 未 ready 切 poster、解码失败 40ms 释放）。
5. **交接**：状态机 `boot→playing→handoff→done`；音频与原片淡出对齐（30.4s 起），不额外淡出。
